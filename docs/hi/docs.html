ओवरव्यू

review-pro एक स्तरित AI कोड-समीक्षा प्रणाली है: छँटाई → संबंधित विशेषज्ञ समीक्षक → संश्लेषण। यह AI एजेंटों द्वारा लिखे गए कोड की समीक्षा AI एजेंटों से करवाता है — AI-जनित कोड की उन वास्तविक विफलताओं को पकड़ने के लिए बनाया गया: मनगढ़ंत API, अति-इंजीनियरिंग, उपेक्षित परिपाटियाँ, अनावश्यक डिपेंडेंसीज़।

यह CLI review-pro कोर (12 समीक्षक कौशल + सबएजेंट + review-pro ऑर्केस्ट्रेटर) को आपके एजेंट टूल में, और स्टैक पैक को आपकी रिपॉजिटरी के .review-pro/ में इंस्टॉल करता है। समर्थित लक्ष्य: opencode · Claude Code · Cursor · Codex।

इंस्टॉल

Claude Code: प्लगइन के रूप में इंस्टॉल करें

इस रिपॉज़िटरी को प्लगइन मार्केटप्लेस के रूप में जोड़ता है, फिर उससे कोर इंस्टॉल करता है। Node.js की ज़रूरत नहीं। स्टैक पैक अब भी CLI से आते हैं।

/plugin marketplace add tufantunc/review-pro
/plugin install review-pro@review-pro

कोई भी प्लेटफ़ॉर्म: इंस्टॉलर CLI

एक बार। इंटरैक्टिव — यह पूछता है कि कौन से प्लेटफ़ॉर्म और कौन से स्टैक पैक इंस्टॉल करने हैं।

npx review-pro init                           # interactive: pick platforms + stacks

नॉन-इंटरैक्टिव (CI)? --target <platform|all|auto> और --no-stacks का उपयोग करें।

प्रति-प्लेटफ़ॉर्म नोट्स

  • opencode — कौशल ~/.config/opencode/skills/ में, एजेंट ~/.config/opencode/agents/ में ($OPENCODE_HOME ओवरराइड करता है)।
  • Claude Code — कौशल ~/.claude/skills/ में, एजेंट ~/.claude/agents/ में (एजेंट का skills: फ़ील्ड इसका रूबरिक प्रीलोड करता है)।
  • Cursor — Cursor के /add-plugin से इंस्टॉल; Cursor में /add-plugin https://github.com/tufantunc/review-pro चलाएँ (रिपॉजिटरी में एक .cursor-plugin/plugin.json आता है)।
  • Codex — कौशल ~/.agents/skills/ में, एजेंट स्वतः ~/.codex/agents/*.toml में बदल जाते हैं। Codex कौशल स्वतः खोज लेता है; एजेंट सत्र के कौशल-समुच्चय को विरासत में लेते हैं।

फिर अपने उपयोग के स्टैक पैक जोड़ें (नीचे), नए कौशल/एजेंट खोजे जाने के लिए अपना टूल पुनर्प्रारंभ करें, और एक समीक्षा चलाएँ।

मैन्युअल इंस्टॉल (Node.js नहीं)

review-pro सादा markdown कौशल और एजेंट हैं — कोई रनटाइम डिपेंडेंसी नहीं। यदि आपके पास Node.js नहीं है (या CLI उपयोग नहीं करना चाहते), फ़ाइलों को हाथ से कॉपी करें:

  1. कोर — core/skills/<name>/ को अपने टूल के कौशल फ़ोल्डर में, और core/agents/*.md को उसके एजेंट फ़ोल्डर में कॉपी करें (ऊपर प्लेटफ़ॉर्म अनुसार पथ)।
  2. स्टैक पैक — stacks/<pack>/ को समीक्षित रिपॉजिटरी के .review-pro/<pack>/ में कॉपी करें।
# example: opencode core + python stack, by hand
cp -R core/skills/*           ~/.config/opencode/skills/
cp    core/agents/*.md        ~/.config/opencode/agents/
mkdir -p .review-pro && cp -R stacks/python .review-pro/python

CLI केवल इन कॉपीज़ को स्वचालित करता है (साथ ही Codex .md→.toml ट्रांसफ़ॉर्म और संस्करण ट्रैकिंग)। मैन्युअल और CLI इंस्टॉल समतुल्य हैं।

स्टैक पैक

पैक समीक्षण के समय समीक्षकों पर भाषा/फ़्रेमवर्क-विशिष्ट संकेत स्तरित करते हैं। किसी रिपॉजिटरी द्वारा उपयोग किए जाने वाले पैक उसके .review-pro/ में इंस्टॉल करें। फ़्रेमवर्क/डोमेन पैक एक भाषा पैक के ऊपर संयोजित होते हैं।

npx review-pro                # interactive multi-select
npx review-pro add python     # one pack, CI-safe
npx review-pro list           # catalog + installed + drift

कैटलॉग (16): python · go · rust · typescript-react · node · php · dotnet · kotlin · swift · flutter · capacitor · nextjs · tanstack-start · react-native · wordpress · ai-ml। उदाहरण: एक Next.js रिपॉजिटरी typescript-react + nextjs सक्रिय करती है; एक LLM ऐप python + ai-ml सक्रिय करता है।

कमांड

कमांडक्या करता है
npx review-proइंटरैक्टिव — .review-pro/ में इंस्टॉल करने के लिए स्टैक चुनें
init [--target <platform>]कोर प्लगइन को किसी टूल के होम में इंस्टॉल करें
uninstall [--target <platform>]किसी टूल के होम से कोर प्लगइन हटाता है (agents + skills)। .review-pro/ में स्टैक पैक प्रभावित नहीं होते।
add <stack>एक स्टैक पैक इंस्टॉल करें (नॉन-इंटरैक्टिव)
remove <stack>इंस्टॉल किए गए पैक को हटाएँ
update [stack]इंस्टॉल किए गए पैक को कैटलॉग संस्करण में ताज़ा करें
listकैटलॉग स्टैक + इंस्टॉल किए गए संस्करण + ड्रिफ़्ट दिखाएँ
doctorइंस्टॉल किए गए पैक सत्यापित करें (संस्करण ड्रिफ़्ट, रोस्टर अखंडता, अनाथ)

समीक्षा चलाएँ

इंस्टॉल + पुनर्प्रारंभ के बाद, उस रिपॉजिटरी में जिसकी आप समीक्षा करना चाहते हैं (एक फ़ीचर ब्रांच पर):

  • सत्र से इस ब्रांच की review-pro से समीक्षा करने को कहें, या
  • review-pro कौशल सीधे कॉल करें।

एजेंट पूरा पाइपलाइन स्वदेशी रूप से चलाता है — git diff, बदली हुई फ़ाइलें पढ़ता है, सक्रिय स्टैक के लिए .review-pro/ को स्कैन करता है, संबंधित समीक्षक सबएजेंट को उनके स्टैक संकेतों के साथ भेजता है, और एक निर्णय संश्लेषित करता है: BLOCK / REQUEST CHANGES / APPROVE। समीक्षण के समय कोई env वैरिएबल नहीं, चलाने के लिए कोई स्क्रिप्ट नहीं।

12 समीक्षक

security · correctness · craft · ai-antipatterns · dry · performance · backend · frontend · a11y · db · api-contract · tests। ai-antipatterns समीक्षक प्रथम-श्रेणी है: मनगढ़ंत API/सिंबल/इम्पोर्ट, मनगढ़ंत कॉन्फ़िग/एनव कुंजी, अनावश्यक डिपेंडेंसीज़, और उपेक्षित मौजूदा हेल्पर्स।

सामान्य प्रश्न

क्या इसे Node.js चाहिए?

केवल इंस्टॉलर CLI को (Node ≥ 18)। प्लगइन स्वयं सादा markdown कौशल और एजेंट हैं, इसलिए मैन्युअल इंस्टॉल किसी भी प्लेटफ़ॉर्म पर Node के बिना काम करता है।

यह एकल “इसकी समीक्षा करो” प्रॉम्प्ट से कैसे अलग है?

एकल प्रॉम्प्ट पूरा diff एक एजेंट को दे देता है और सब कुछ माँगता है। review-pro पहले छँटाई करता है, केवल संबंधित विशेषज्ञों को सीमित संदर्भ के साथ समानांतर चलाता है, फिर संश्लेषित करता है — इसलिए छोटे बदलाव सस्ते रहते हैं और बड़े बदलाव गहराई में जाते हैं, गंभीरता अति-रिपोर्टिंग के विरुद्ध अंशांकित।

स्टैक पैक कहाँ से आते हैं?

कैटलॉग इस पैकेज के अंदर आता है, प्रकाशन के समय स्नैपशॉट किया गया। नए पैक एक नया संस्करण प्रकाशित होने के बाद दिखते हैं। अपना जोड़ने के लिए रिपॉजिटरी में stacks/CONTRIBUTING.md देखें।

क्या यह सच में क्रॉस-प्लेटफ़ॉर्म है?

हाँ — एक ही कैनोनिकल स्रोत opencode, Claude Code, Cursor और Codex में इंस्टॉल होता है। Codex एजेंट स्वतः TOML में बदल जाते हैं; बाकी वही markdown एजेंट उपयोग करते हैं।

चरणों में सोचने वाली कोड समीक्षा।
