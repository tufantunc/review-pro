# Site Multi-Language Support — Design Spec

**Date:** 2026-06-27
**Status:** Approved (brainstormed)
**Relation:** Adds i18n to the GitHub Pages site under `docs/` (no relation to the CLI/plugin).

---

## 1. Goal

Add multi-language support to the static marketing/docs site served at
`https://tufantunc.github.io/review-pro/`. Seven languages: **English**
(canonical, root) + **Turkish, Chinese (Simplified), Hindi, German, French,
Dutch**. A flag dropdown in the nav switches language; browser language is
detected on first visit and the choice persists.

## 2. Decisions (from brainstorm)

| # | Decision | Choice |
|---|---|---|
| 1 | Selector | Dropdown: one flag button opens a list of 7 flags + names |
| 2 | First visit | Detect `navigator.language`; redirect once if a supported lang matches |
| 3 | Persistence | `localStorage.rp_lang` |
| 4 | Approach | Per-language static HTML (best SEO, no-JS content) |
| 5 | Authoring | Generated by a build script from a single template + JSON dictionaries (no drift) |
| 6 | Demo | Animated hero demo stays **English** in all languages (technical feel) |
| 7 | Flags | Inline **SVG** flags (emoji render as letter-pairs on Windows) |

## 3. Architecture — single source, static output

```
docs-src/                         ← SOURCE (edited here)
  index.html                      ← template with {{tokens}} (copy lives in JSON)
  docs.html
  i18n/{en,tr,zh,hi,de,fr,nl}.json
scripts/build-site.js             ← generator (Node >=18, zero deps)
docs/                             ← OUTPUT (committed, served by Pages)
  index.html  docs.html           ← English (root, existing URLs preserved)
  site.css  favicon.ico  .nojekyll
  tr/ zh/ hi/ de/ fr/ nl/         ← each: index.html + docs.html
```

English stays at root so existing links, the npm README badge, and
`https://tufantunc.github.io/review-pro/` keep working unchanged. Other
languages live one level down. Editing happens in one place (template + 7
JSON files); the build regenerates all 14 pages idempotently.

## 4. URL structure & cross-page navigation

- **EN:** `/review-pro/` and `/review-pro/docs.html` (unchanged).
- **Others:** `/review-pro/<lang>/index.html`, `/review-pro/<lang>/docs.html`.
- **Stay in-language:** within `<lang>/`, links are relative (`docs.html`,
  `index.html`) so Home↔Docs stays in the current language. Root EN keeps its
  existing absolute `/review-pro/...` links.
- **Brand link:** set per page — `<lang>/` for translated pages, `/review-pro/`
  for EN root.
- **Anchor links** (`#how`, `#capabilities`) on `docs.html`: currently point to
  `/review-pro/#how` (would jump to EN root). Build rewrites them to
  `<lang-root>/index.html#how` per language.
- **Shared assets:** `site.css` and the inline SVG favicon are referenced via
  the absolute path `/review-pro/site.css` from every page so a single copy is
  shared (subdirs do not duplicate CSS). The data-URI favicon is already inline.

## 5. Browser-language detection & persistence

A small inline script at the end of `<head>` on every page (runs before paint
to avoid a flash):

1. If `localStorage.rp_lang` exists → user already chose; record current and do
   nothing (no redirect).
2. Else read `navigator.language` / `navigator.languages`, match against the
   supported set `[en,tr,zh,hi,de,fr,nl]` (prefix match, e.g. `de-AT` → `de`).
3. If the match differs from the **current** page language → redirect once to
   the **same page** in the matched language (`docs.html`→`/<lang>/docs.html`,
   index→`/<lang>/`), falling back to the language root.
4. Set `localStorage.rp_lang = <current>` so it never repeats.

Guards: compare against current page lang (no loop); no redirect for bots
(best-effort UA check); only fires when no prior choice exists. Detection never
overrides an explicit choice.

## 6. Templating — `{{token}}` replacement (mustache-style, no parser)

The build does plain string replacement over the template document — no HTML
parser, no runtime dependency.

- `{{key}}` → **HTML-escaped** value (for plain-text strings; safe in text and
  attribute contexts).
- `{{{key}}}` → **raw HTML** value (for strings that contain inline tags:
  `<strong>`, `<em>`, `<code>`, `<a>`).
- Attribute values, e.g. `<meta name="description" content="{{meta.desc}}">`,
  use escaped tokens.
- English is also produced from `en.json` (true single source — the template's
  tokens hold no literal copy).
- **Build asserts** no `{{` remains in any output file (catches missing keys).

## 7. Language selector (nav dropdown)

Markup (same on every page; the current page's own entry is marked active):

```html
<div class="lang" aria-label="Language">
  <button class="lang__btn" type="button" aria-haspopup="true"
          aria-expanded="false">
    <svg class="lang__flag">…current flag…</svg>
    <span class="lang__code">EN</span>
  </button>
  <ul class="lang__menu" role="menu" hidden>
    <li><a href="/review-pro/"     >{EN svg} English</a></li>
    <li><a href="/review-pro/tr/"  >{TR svg} Türkçe</a></li>
    <li><a href="/review-pro/zh/"  >{ZH svg} 中文</a></li>
    <li><a href="/review-pro/hi/"  >{HI svg} हिन्दी</a></li>
    <li><a href="/review-pro/de/"  >{DE svg} Deutsch</a></li>
    <li><a href="/review-pro/fr/"  >{FR svg} Français</a></li>
    <li><a href="/review-pro/nl/"  >{NL svg} Nederlands</a></li>
  </ul>
</div>
```

- **Switching = following a link** to the target language's root. Works without
  JS for navigation.
- The open/close toggle is small vanilla JS: click button to toggle, click
  outside closes, `Escape` closes, menu links are keyboard-focusable, ARIA
  `aria-expanded` updated. Focus moves into the menu on open.
- Flags are **inline SVG** (7 small flags, no dependency; consistent across
  macOS/Linux/Windows). The current page's button shows its own flag + code.
- **Mobile:** the existing 640px rule hides nav links except Docs + Install.
  The `.lang` selector is **exempt** so it stays visible as a compact flag.

## 8. CSS

Append `.lang`, `.lang__btn`, `.lang__menu`, `.lang__flag`, `.lang__code`,
active/hover/focus states to `site.css`. Style matches the existing
oat-cream/pine-green palette and nav sizing. Selector placed at the end of
`.nav__links`. On phones it collapses to flag-only.

## 9. SEO

- Each page sets `<html lang="en|tr|zh|hi|de|fr|nl">`. All chosen languages are
  LTR, so no `dir` change is needed.
- `hreflang` alternates on every page:
  ```html
  <link rel="alternate" hreflang="en" href="https://tufantunc.github.io/review-pro/">
  <link rel="alternate" hreflang="tr" href="…/tr/">
  … (zh, hi, de, fr, nl) …
  <link rel="alternate" hreflang="x-default" href="https://tufantunc.github.io/review-pro/">
  ```
- `<title>` and `<meta name="description">` are tokenized and translated.

## 10. Fonts (hi/zh)

IBM Plex Sans covers Latin only; Hindi (Devanagari) and Chinese fall back to
system fonts. The `font-family` stack gains
`"Noto Sans Devanagari", "Noto Sans SC"` so the fallback is consistent. A
webfont can be added later if the fallback looks poor; not in this scope.

## 11. Translation scope

**Translated** (tokenized): nav labels, hero (eyebrow/title/sub/CTAs), pipeline
section (3 stages × title/body/tags), capabilities (eyebrow/title/lead/cards),
install section (eyebrow/title/lead/**notes**, not code), footer (statement,
Home/Docs labels), all of `docs.html` (headings, paragraphs, commands table,
manual-install steps, FAQ), `<title>`, meta description.

**Stays English** (not tokenized, copied verbatim):
- Brand name `review-pro`.
- Code/command blocks in `<pre><code>` **including their `#` comments**.
- Pill labels that are proper nouns: reviewer names (security, correctness…),
  stack packs (python, go…), platforms (opencode, Cursor, Claude Code, Codex).
- File paths and toolhomes (`~/.config/…`, `.review-pro/`).
- The **entire animated hero demo** — stage labels, reviewer names, verdict
  label, finding descriptions (decision 6).
- `GitHub`, `npm` proper-noun labels.

Translations are authored by the assistant; the user reviews (Turkish in
particular).

## 12. Build tooling

- `scripts/build-site.js` — Node >=18, zero dependencies. Reads
  `docs-src/{index,docs}.html` + the 7 JSON dictionaries; for each language
  performs token replacement (escape vs raw per brace style); writes EN to
  `docs/` root and the others to `docs/<lang>/`. Asserts no leftover `{{`.
  Idempotent; safe to re-run.
- Run manually: `node scripts/build-site.js`. No package.json changes required
  (no deps); optionally documented in `RELEASING.md` so site edits are
  followed by a rebuild before commit.
- `.nojekyll` already present → generated HTML/CSS is served as-is by Pages.

## 13. Risks & edge cases

- **Token in mixed content:** raw `{{{key}}}` is used wherever a translated
  sentence contains inline tags; plain `{{key}}` elsewhere. Kept consistent by
  convention.
- **Attribute safety:** escaped tokens used in `content="…"`, `title`, etc.
- **Hindi/Chinese font:** system fallback + Noto in stack (§10).
- **Redirect on first visit:** guarded against loops and bots; never overrides
  an explicit choice.
- **Shared CSS path:** absolute `/review-pro/site.css` (matches existing
  `/review-pro/…` link convention); verified to work from subdirs.

## 14. Verification

- `node scripts/build-site.js` → 14 pages emitted; grep asserts zero `{{`
  leftovers across `docs/**`.
- Manual pass: open each language from the dropdown → copy translated, demo
  English, code/commands English, Home↔Docs stays in-language, brand link goes
  to the language root.
- Detection: devtools override `navigator.language` (e.g. `de-DE`) on a clean
  profile → redirects to `/de/` once; revisit stays.
- `localStorage.rp_lang` set after first load; switching via dropdown keeps the
  chosen language across reloads.
- Lighthouse a11y audit on `en` and `tr` (selector keyboard nav, ARIA,
  contrast).
- Verify `<html lang>` and `hreflang` per page; mobile nav keeps the selector
  visible.

## 15. Out of scope

- A webfont for Hindi/Chinese (system fallback this round).
- Translating the animated demo.
- A build step running on GitHub Pages (output is committed static HTML).
- Right-to-left languages (none in the set).
