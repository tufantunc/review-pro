### Medium
- **[Medium] `cli/tests/doctor.test.ts:51` / `cli/src/lib/doctor.ts:54`: no test fails if the guard that stops a pack from being reported twice is removed**
  - **The gap:** `checkStrayPacks` uses the `!m.reviewers.includes(r)` check to skip packs the manifest declares. Without it, a declared pack for an unknown reviewer such as `ghost.md` is reported twice: once by `checkDeclaredPacks` (lines 42-43) and once by `checkStrayPacks`.
  - **Why no test catches it:** the only test with a declared, unknown reviewer asserts with `.some(...)`, so it still passes on a duplicate. Both new tests use undeclared reviewers.
  - **Impact:** this PR moved exactly this logic into two helpers. A duplicate would print twice to users via `cli/src/commands/doctor.ts:12`.
  - **Remedy:** make the "reports unknown reviewer in pack" assertion exact. Either expect both diagnoses the fixture produces: `missing-pack` for `security`, then `unknown-reviewer` for `'ghost.md'`. Or write `security.md` in that fixture and expect just the one `unknown-reviewer` entry.
  - verification: partly refuted. The gap stands. The reviewer's original remedy (expect only the single `unknown-reviewer` entry) is wrong: that fixture never writes `security.md`, so `doctor.ts:40-41` also emits `missing-pack` and the proposed assertion would fail on correct code (`cli/tests/doctor.test.ts:46-49`). The remedy above is the corrected one.

- **[Medium] `cli/src/lib/doctor.ts:48`: the unknown-reviewer rule is still split across the two pack checks**
  - **The issue:** the refactor moves the old loops into functions but keeps the tangle.
    - "Pack targets an unknown reviewer" is half in the `else if` of `checkDeclaredPacks` and half in `checkStrayPacks`.
    - The second half then needs the manifest guard and a comment to avoid reporting a pack twice. This is the guard the finding above says is untested.
    - Pack names round-trip between `${r}.md` and `f.slice(0, -3)`.
  - **Remedy:** split the checks by concern over a set of bare reviewer names, like `listAgentNames` at `cli/src/lib/plugin.ts:187`:
    - each `m.reviewers` entry not in the set → `missing-pack`
    - each pack name not in `knownReviewers` → `unknown-reviewer`

    This removes the guard, the comment and the slicing. Only output order changes, and nothing depends on it: the only caller is `cli/src/commands/doctor.ts:10`, and no test checks the order of a multi-item list.
  - verification: partly refuted, and two claims fall:
    - "Each helper needs only two of its four parameters" is false: both read all four (`doctor.ts:37-44`, `48-56`).
    - "The remedy gives an identical diagnosis set" fails in one edge case. `parseManifest` does not remove duplicates (`manifest.ts:15-17`), so a manifest listing the same unknown reviewer twice currently gets two diagnoses; the remedy would give one.

    The core point stands.
