# Stack pack: capacitor — a11y
extends: core/skills/a11y/SKILL.md

## Stack-specific signals
- Assumption that "native a11y doesn't apply" — the WebView exposes its DOM a11y tree to VoiceOver/TalkBack, so missing labels/roles/alt in the web UI reaches the screen reader unannounced.
- Tap targets below ~44pt (iOS) / 48dp (Android), or controls placed under the notch/safe area where they're unreachable.
- Native overlays (splash, `Dialog` alerts, camera/permission prompts, InAppBrowser) without accessible labels or focus management; no focus return when the overlay closes.
- `Haptics` used as the **only** feedback for an action → invisible to screen-reader users; no audible/visible equivalent.
- Fixed `px` font sizes ignoring Dynamic Type (iOS `UIContentSizeCategory`) / Android font scale; `prefers-reduced-motion`/`prefers-contrast` ignored.
- Contrast regression in the shipped WebView UI; icon-only buttons without an accessible name; informative images missing `alt`.
- Focus order broken when native sheets/modals open over the WebView; content scroll region not keyboard-focusable.

## Stack-specific remedies
- Treat the WebView UI with full web-a11y rigor (labels/roles/alt); keep ≥44/48dp targets out of safe areas; trap and restore focus around native overlays; pair haptics with visible/announced feedback; honor system font scale and reduced-motion/contrast.

## Stack-specific severity guidance
- Unlabeled control or focus not managed across a native overlay: High.
- Sub-min-size tap target / contrast regression / haptics-only feedback: Medium.
