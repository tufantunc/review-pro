Überblick

review-pro ist ein gestaffeltes KI-Codeprüfungssystem: Triage → relevante Spezialisten-Prüfer → Synthese. Es prüft Code, der von KI-Agenten geschrieben wurde, mit KI-Agenten — gebaut, um die Fehlermuster zu erfassen, die KI-generierter Code tatsächlich ausliefert: halluzinierte APIs, Über-Engineering, ignorierte Konventionen, überflüssige Abhängigkeiten.

Diese CLI installiert den review-pro-Kern (13 Prüfer-Skills + Subagenten + den review-pro-Orchestrator) in dein Agenten-Tool und die Stack-Pakete in die .review-pro/ deines Repos. Unterstützte Ziele: opencode · Claude Code · Cursor · Codex.

Installation

Claude Code: als Plugin installieren

Fügt dieses Repository als Plugin-Marketplace hinzu und installiert den Kern von dort. Kein Node.js nötig. Stack-Pakete kommen weiterhin über die CLI.

/plugin marketplace add tufantunc/review-pro
/plugin install review-pro@review-pro

Jede Plattform: Installer-CLI

Einmalig. Interaktiv — sie fragt, welche Plattformen und welche Stack-Pakete installiert werden sollen.

npx review-pro init                           # interactive: pick platforms + stacks

Nicht-interaktiv (CI)? Verwende --target <platform|all|auto> und --no-stacks.

Hinweise pro Plattform

  • opencode — Skills nach ~/.config/opencode/skills/, Agenten nach ~/.config/opencode/agents/ ($OPENCODE_HOME überschreibt).
  • Claude Code — Skills nach ~/.claude/skills/, Agenten nach ~/.claude/agents/ (das Feld skills: des Agenten lädt seine Rubrik vor).
  • Cursor — über Cursor /add-plugin installiert; führe /add-plugin https://github.com/tufantunc/review-pro in Cursor aus (das Repo liefert eine .cursor-plugin/plugin.json mit).
  • Codex — Skills nach ~/.agents/skills/, Agenten automatisch zu ~/.codex/agents/*.toml transformiert. Codex entdeckt Skills automatisch; Agenten erben den Skill-Satz der Session.

Füge dann die Stack-Pakete hinzu, die du nutzt (unten), starte dein Tool neu, damit die neuen Skills/Agenten entdeckt werden, und führe eine Prüfung aus.

Manuelle Installation (ohne Node.js)

review-pro besteht aus reinen Markdown-Skills und -Agenten — keine Laufzeitabhängigkeit. Wenn du kein Node.js hast (oder die CLI nicht nutzen möchtest), kopiere die Dateien von Hand:

  1. Kern — kopiere core/skills/<name>/ in den Skills-Ordner deines Tools und core/agents/*.md in dessen Agenten-Ordner (Pfade wie pro Plattform oben).
  2. Stack-Pakete — kopiere stacks/<pack>/ in die .review-pro/<pack>/ des geprüften Repos.
# example: opencode core + python stack, by hand
cp -R core/skills/*           ~/.config/opencode/skills/
cp    core/agents/*.md        ~/.config/opencode/agents/
mkdir -p .review-pro && cp -R stacks/python .review-pro/python

Die CLI automatisiert nur diese Kopien (plus die Codex .md→.toml-Transformation und Versionsverfolgung). Manuelle und CLI-Installationen sind gleichwertig.

Stack-Pakete

Pakete schichten sprach-/frameworkspezifische Signale zur Prüfzeit auf die Prüfer. Installiere die, die ein Repo nutzt, in dessen .review-pro/. Framework-/Domain-Pakete setzen auf einem Sprachpaket auf.

npx review-pro                # interactive multi-select
npx review-pro add python     # one pack, CI-safe
npx review-pro list           # catalog + installed + drift

Katalog (16): python · go · rust · typescript-react · node · php · dotnet · kotlin · swift · flutter · capacitor · nextjs · tanstack-start · react-native · wordpress · ai-ml. Beispiele: ein Next.js-Repo aktiviert typescript-react + nextjs; eine LLM-App aktiviert python + ai-ml.

Prüfung ausführen

Nach Installation + Neustart, im Repo, das du prüfen willst (auf einem Feature-Branch):

  • bitte die Session, diesen Branch mit review-pro zu prüfen, oder
  • rufe den review-pro-Skill direkt auf.

Der Agent führt die gesamte Pipeline nativ aus — git diff, liest geänderte Dateien, durchsucht .review-pro/ nach aktiven Stacks, leitet die relevanten Prüfer-Subagenten mit ihren Stack-Signalen weiter und synthetisiert ein Urteil: BLOCK / REQUEST CHANGES / APPROVE. Keine Env-Vars, keine Skripte zur Prüfzeit.

Die 13 Prüfer

security · correctness · craft · ai-antipatterns · dry · performance · backend · frontend · a11y · db · api-contract · tests · spec. Der ai-antipatterns-Prüfer ist erstklassig: halluzinierte APIs/Symbole/Imports, erfundene Config-/Env-Keys, überflüssige Abhängigkeiten und ignorierte bestehende Helfer.

FAQ

Braucht es Node.js?

Nur die Installer-CLI (Node ≥ 18). Das Plugin selbst besteht aus reinen Markdown-Skills und -Agenten, daher funktioniert die manuelle Installation ohne Node auf jeder Plattform.

Worin unterscheidet sich das von einem einzelnen „Prüfe das“-Prompt?

Ein Prompt übergibt den gesamten Diff an einen Agenten und fordert alles. review-pro triagiert zuerst, führt nur die relevanten Spezialisten parallel mit eingegrenztem Kontext aus und synthetisiert dann — sodass kleine Änderungen billig bleiben und große tief gehen, mit einem gegen Übermeldungen kalibrierten Schweregrad.

Woher kommen die Stack-Pakete?

Der Katalog wird innerhalb dieses Pakets mitgeliefert, zum Veröffentlichungszeitpunkt als Schnappschuss. Neue Pakete erscheinen, nachdem eine neue Version veröffentlicht wurde. Siehe stacks/CONTRIBUTING.md im Repo, um eigene hinzuzufügen.

Ist es wirklich plattformübergreifend?

Ja — eine kanonische Quelle installiert sich in opencode, Claude Code, Cursor und Codex. Codex-Agenten werden automatisch zu TOML transformiert; die anderen verwenden dieselben Markdown-Agenten.
