Vue d'ensemble

review-pro est un système de revue de code IA par paliers : triage → relecteurs spécialistes pertinents → synthèse. Il examine le code écrit par des agents IA à l'aide d'agents IA — conçu pour capter les défaillances que le code généré par IA embarque réellement : APIs hallucinées, sur-ingénierie, conventions ignorées, dépendances superflues.

Cette CLI installe le cœur de review-pro (12 skills de relecture + sous-agents + l'orchestrateur review-pro) dans ton outil d'agents, et les packs de stack dans le .review-pro/ de ton dépôt. Cibles prises en charge : opencode · Claude Code · Cursor · Codex.

Installation

Une seule fois. Interactive — elle demande quelles plateformes et quels packs de stack installer.

npx review-pro init                           # interactive: pick platforms + stacks

Non-interactive (CI) ? Utilise --target <platform|all|auto> et --no-stacks.

Notes par plateforme

  • opencode — skills vers ~/.config/opencode/skills/, agents vers ~/.config/opencode/agents/ ($OPENCODE_HOME prime).
  • Claude Code — skills vers ~/.claude/skills/, agents vers ~/.claude/agents/ (le champ skills: de l'agent précharge sa grille).
  • Cursor — installé via /add-plugin de Cursor ; exécute /add-plugin https://github.com/tufantunc/review-pro dans Cursor (le dépôt embarque un .cursor-plugin/plugin.json).
  • Codex — skills vers ~/.agents/skills/, agents auto-transformés en ~/.codex/agents/*.toml. Codex découvre les skills automatiquement ; les agents héritent du jeu de skills de la session.

Ajoute ensuite les packs de stack que tu utilises (ci-dessous), redémarre ton outil pour que les nouvelles skills/agents soient découverts, et lance une revue.

Installation manuelle (sans Node.js)

review-pro n'est que des skills et agents markdown — aucune dépendance d'exécution. Si tu n'as pas Node.js (ou préfères ne pas utiliser la CLI), copie les fichiers à la main :

  1. Cœur — copie core/skills/<name>/ dans le dossier des skills de ton outil et core/agents/*.md dans son dossier des agents (chemins selon la plateforme ci-dessus).
  2. Packs de stack — copie stacks/<pack>/ dans le .review-pro/<pack>/ du dépôt examiné.
# example: opencode core + python stack, by hand
cp -R core/skills/*           ~/.config/opencode/skills/
cp    core/agents/*.md        ~/.config/opencode/agents/
mkdir -p .review-pro && cp -R stacks/python .review-pro/python

La CLI se contente d'automatiser ces copies (plus la transformation Codex .md→.toml et le suivi de version). Les installations manuelle et par CLI sont équivalentes.

Packs de stack

Les packs ajoutent aux relecteurs, au moment de la revue, des signaux propres au langage/framework. Installe ceux qu'un dépôt utilise dans son .review-pro/. Les packs de framework/domaine se composent sur un pack de langage.

npx review-pro                # interactive multi-select
npx review-pro add python     # one pack, CI-safe
npx review-pro list           # catalog + installed + drift

Catalogue (14) : python · go · rust · typescript-react · node · php · dotnet · kotlin · swift · flutter · nextjs · react-native · wordpress · ai-ml. Exemples : un dépôt Next.js active typescript-react + nextjs ; une app LLM active python + ai-ml.

Lancer une revue

Après installation + redémarrage, dans le dépôt à examiner (sur une branche de fonctionnalité) :

  • demande à la session de examiner cette branche avec review-pro, ou
  • invoque directement la skill review-pro.

L'agent exécute tout le pipeline nativement — git diff, lit les fichiers modifiés, parcourt .review-pro/ pour les stacks actifs, répartit les sous-agents relecteurs pertinents avec leurs signaux de stack, et synthétise un verdict : BLOCK / REQUEST CHANGES / APPROVE. Aucune variable d'env, aucun script à lancer au moment de la revue.

Les 12 relecteurs

security · correctness · craft · ai-antipatterns · dry · performance · backend · frontend · a11y · db · api-contract · tests. Le relecteur ai-antipatterns est de premier plan : APIs/symboles/imports hallucinés, clés de config/env inventées, dépendances superflues et helpers existants ignorés.

FAQ

Faut-il Node.js ?

Seule la CLI d'installation en a besoin (Node ≥ 18). Le plugin lui-même n'est que des skills et agents markdown, donc l'installation manuelle fonctionne sans Node sur toute plateforme.

En quoi cela diffère-t-il d'un simple prompt « examine ça » ?

Un seul prompt remet tout le diff à un agent et demande tout. review-pro trie d'abord, n'exécute en parallèle que les spécialistes pertinents avec un contexte délimité, puis synthétise — ainsi les petits changements restent peu coûteux et les grands vont en profondeur, avec une sévérité calibrée contre le sur-signalement.

D'où viennent les packs de stack ?

Le catalogue est livré dans ce paquet, sous forme d'instantané à la publication. De nouveaux packs apparaissent après la publication d'une nouvelle version. Voir stacks/CONTRIBUTING.md dans le dépôt pour ajouter les tiens.

Est-ce vraiment multiplateforme ?

Oui — une source canonique s'installe dans opencode, Claude Code, Cursor et Codex. Les agents Codex sont auto-transformés en TOML ; les autres consomment les mêmes agents markdown.
